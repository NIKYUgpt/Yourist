# Диалоговая выборка v1

Зафиксирована 05.11.2026 до просмотра результатов моделей. 18 синтетических диалогов:
6 development (известные темы) и 12 evaluation (новые формулировки и семейства).
Один случай — один диалог с одной оцениваемой последней репликой. Никакая часть
одного семейства не находится в другом split. Целевые статьи evaluation не входят
в разметку прежних labor_basic/hard/compound; это не исключает знаний моделей о них.

Разметка `synthetic_unreviewed`: подготовлена ИИ по текстам загруженного корпуса
ТК РФ на 27.10.2026. Двух независимых человеческих аннотаций пока нет. Набор
пригоден для пилотного сравнения и поиска ошибок, но не является независимым
экспертным подтверждением юридической точности. Вопросы не содержат реальных ПД.
Прежние промпты и словарь до прогона не меняются.

Виды: местоименная ссылка, новое обстоятельство, исправление, смена темы,
несколько вопросов и намеренно неверный предыдущий ответ. Обоснование каждой
метки находится в `rationale`; акт задан стабильным `source:external_id`.
Стенд проверяет наличие и действительность каждой целевой статьи на дату набора
и записывает хеш её текста. Он не доказывает достаточность этой статьи для ответа.

Из каталога backend:

```powershell
python -m app.evaluation.dialog_retrieval --dataset evaluation/dialogs_v1.json --split development --out evaluation/results/dialog-dev
python -m app.evaluation.dialog_retrieval --dataset evaluation/dialogs_v1.json --split evaluation --out evaluation/results/dialog-eval
```

Используются только локальные Ollama-профили embed/analyze; конфигурация БД не меняется.
A — последняя реплика, B — она и два предыдущих вопроса, C — переформулировка.
Все варианты получают одинаковые 24 кандидата по своему запросу, оцениваются первые 8;
кандидаты сохраняются для следующего эксперимента с реранкером. Explicit-подъём
номера статьи отключён для всех вариантов, чтобы выдуманный номер не давал преимущества C.
Поиск во всех вариантах использует тот же текущий словарь и гибридный RRF.

Снимок БД фиксируется read-only repeatable-read транзакцией. Сохраняются SHA-256
набора/промпта/кода, Git commit/dirty, модели/options/digest, хеши корпуса и индекса,
порядок методов с seed 20261105, выдача, ошибки и fallback, время. Повторный запуск
требует нового каталога, результаты не затираются. Сбой оставляет частичный JSON
со статусом failed; такой результат нельзя считать полным прогоном.

Метрики: macro Recall@8 по уникальным (акт, статья) и MRR@8 по рангу фрагмента.
95% percentile bootstrap разниц — парный по диалогам, 2000 повторений. При 12
диалогах интервалы нестабильны, статистическая мощность мала. Порядок перемешан,
но прогрев CPU/GPU не стандартизован; задержка — диагностическая величина.

После просмотра evaluation-результатов не подбирать на них промпт или параметры.
Для последующего улучшения нужна новая оценочная версия либо заранее фиксированный
вариант, который сравнивается без настройки. При изменении разметки — новая версия
набора и отдельный пересчёт, исходные результаты сохраняются.

Отличие от [полного протокола](../../docs/experiments/dialog-context-protocol.md):
человеческая независимая разметка и слепая оценка сохранения обстоятельств ещё
предстоят. Их не заменяет автоматический recall.
