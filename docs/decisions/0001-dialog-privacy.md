# Диалоги: история и персональные метки

Дата: 05.11.2026. Решение для первой реализации диалогов.

## Задача

Уточнение «А если прошло два месяца?» требует предыдущих обстоятельств. При этом
метка `[ФИО_1]` в разных репликах не должна обозначать разных людей. Ранее таблица
меток существовала только во время одного запроса, а в БД сохранялся обезличенный текст.

## Решение

- История диалога, его владелец, дата применяемых норм и порядок сообщений — в PostgreSQL.
- Исходные значения меток — только в памяти `deid`, отдельно для каждого сеанса
  и владельца. API получает копию для восстановления текущего ответа; в БД её не пишет.
- Срок жизни — 24 часа **от создания**, без продления при обращении. Настройка
  `DEID_SESSION_TTL_SECONDS`, минимум 60 секунд, максимум 7 суток.
- После истечения срока или перезапуска `deid` продолжение возвращает 409. История
  остаётся доступна с метками. Для новых сообщений нужно создать новый диалог.
  Нельзя незаметно создавать пустую таблицу под прежним идентификатором.
- Не более 256 сеансов по умолчанию (`DEID_MAX_SESSIONS`). На сеанс — не более
  256 значений и 32768 символов исходных значений. Переполнение не вытесняет чужой
  активный сеанс и не сохраняет частично обработанное сообщение.
- Проверка срока выполняется при обращении и каждые 60 секунд. Истёкший сеанс
  недоступен сразу; физическая очистка неиспользуемой записи — при ближайшей уборке.
- Удаление диалога удаляет таблицу меток в `deid` и его сообщения в БД.

Сервис `deid` в этой версии запускается **в одном процессе и одном экземпляре**.
Несколько API-процессов могут обращаться к нему по HTTP. Режим обезличивания внутри
API предназначен для однопроцессной разработки. Для нескольких экземпляров `deid`
понадобится отдельное решение о разделяемом хранилище и защите персональных данных.

## Почему так

Сохранение исходных значений в общей БД расширило бы существующую границу приватности.
Шифрованное постоянное хранилище потребовало бы отдельного управления ключами,
доступом, резервными копиями и удалением. Временная память позволяет реализовать
диалоги без этой зависимости; цена — невозможность продолжить сеанс после рестарта.
Это инженерное ограничение, а не утверждение о соответствии конкретному закону.

## Проверки и научные границы

Автотесты проверяют постоянство меток, разделение владельцев и сеансов, истечение
срока, удаление, сбой операции и конкурентный доступ. Они не измеряют полноту
распознавания персональных данных. Качество поиска с историей нужно сравнивать
отдельно: одинаковые уточнения и корпус, поиск без контекста и с контекстом,
ожидаемые статьи, задержка и ошибки преобразования запроса.
