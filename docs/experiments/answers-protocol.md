## Процедура A

Из `backend`:

```powershell
.\.venv\Scripts\python.exe -m app.evaluation.answer_dataset evaluation/answers_v1.json
```

Пакеты `evaluation/annotation/answers-v1/reviewer-a.json` и `reviewer-b.json`
передаются **разным людям**. Каждый независимо заполняет `Label` по соседней
`schema.json`: вывод относительно явно заданного утверждения, условия, исключения,
обоснование, точные нормы с редакцией, цитатой и SHA-256 текста. Если источника
недостаточно, отметить это; не подменять неопределённость догадкой. Компетенции и
дата сдачи обязательны. Исходные файлы сданных разметок сохраняются неизменно.

Импорт не затирает исходный набор:

```powershell
python -m app.evaluation.answer_dataset evaluation/answers_v1.json --reviews a.json b.json --out independently-reviewed.json
```

Затем организатор сохраняет решение по каждому расхождению в отдельном JSON
`{dataset_sha256, cases: {case_id: {reviewer, completed_on, resolution, label}}}`.
Импорт с `--adjudications` выполняется снова от исходного набора и обоих пакетов.
До этого `gold` отсутствует, даже если два класса совпали. Проверка структуры не
доказывает независимость или квалификацию людей — это удостоверяет организатор.
Согласие классов и Cohen's kappa считаются отдельно для answerability и decision;
условия и нормы требуют содержательного разрешения расхождений. При вырожденной
таблице kappa = null. Идентификатор семейства — единица группировки.

## Сравнения B и C

Один генератор, одинаковый формат и бюджет ответа. B0 без источников; B1 простой
лексический поиск; B2 текущий гибрид без реранкера; B3 B2 + отдельный проверяющий
и не более одного исправления. O только с проверенным gold-контекстом, отдельно
от рейтинга. Смена генератора — отдельная серия. Главный будущий контраст B3–B2.

C-navigation: выбор по оглавлению без векторов; C-hybrid: такой же выбор поверх
B2; C-missing: B2 + проверяющий с предложениями пропущенных статей, проверка
существования/редакции по корпусу и одно исправление. Эти три изменения оцениваются
отдельно. MCP — транспорт доступа к тем же функциям, сам по себе не метод поиска.

Новые механизмы — исследовательские прототипы; не меняют продуктовый поиск.
Предварительные пределы: 4 вызова инструментов, 24 тысячи символов их результатов,
60 секунд на чтение корпуса; 180 секунд на вызов модели, 900 секунд на случай,
2048 выходных токенов на генерацию, 1024 на проверку/навигацию. Рекурсивного агента
и скрытых повторов нет. Сбой каждого шага и фактически потраченное время сохраняются.

## Качество, время и стоимость

Правильный JSON и существующая статья не означают правильный ответ. Основная
метрика — все обязательные вопросы, условия и отсутствие существенного
противоречия в тексте. Она требует независимой оценки. Пока её нет, качество
**unresolved**, показываются границы S/N .. (S+U)/N и покрытие. Ошибки генерации
и неверный формат — операционные неуспехи; сбой оценщика не равен правовой ошибке.
Вердикт продуктового проверяющего не используется как оценка собственного качества.

Оценочные ответы выдаются людям с непрозрачными ID без названия модели/метода.
Для решения о превосходстве нужны проверенный gold, калибровка оценщиков и больший
набор. Парный bootstrap по семействам допустим после заполнения оценок, повторные
генерации сначала усредняются внутри случая. При незавершённых оценках вывод о
превосходстве запрещён. Четыре семейства не дают надёжной оценки переноса.

Сохраняются все попытки, ошибки, исходные ответы, порядок, seed, модель/digest,
промпты/код/данные, состояние прогрева, время клиента и доступные длительности
Ollama отдельно. P90 — nearest rank ceil(0.9*n). Таймаут — цензурированная попытка,
а не известное время завершения. Стоимость без тарифа/учёта электричества = null,
не 0. API в этом пилоте не используется; затраты подготовки/разметки отдельно.

## D: восстановление

Синтетические имена, несколько лиц и падежей; исходная подстановка против локальной
морфологии с разрешёнными заменами только внутри меток. Неоднозначность — отказ от
исправления. Правовой текст вне меток проверяется побайтно. Пол и идентичность не
угадываются по имени. Отдельно измеряются пропуски/лишняя маскировка и путаница лиц.
Пилот не подтверждает качество на реальных персональных данных.

## Уточнение стенда по техническим прогонам 15.11

Начальные smoke-серии сохранены отдельно: свободный JSON ломал формат, общая схема
допускала повторение issue ID. В окончательном стенде схема ограничивает число
issues и их допустимые ID; после генерации ещё проверяются уникальность и покрытие.
JSON Schema не заменяет проверку результата: даже проверяющая модель нарушала её.

Первая свободная навигация также не дала корректного чтения: модель придумывала
названия инструментов и передавала название главы вместо статьи. Два C-hybrid
запроса достигли 8191 входного токена при контексте 8192 — вероятна обрезка.
Эту серию нельзя использовать для вывода о пользе навигации. После её разбора
прототип уточнён: компактное оглавление → выбор одного существующего раздела →
до двух статей из него. Это следующая версия контроллера, отдельный прогон.
Бюджеты прежние. Поведение при отсутствии источников явно отличается: только B0
разрешены собственные знания; остальные варианты должны отметить недостаток норм.
Достижение границы контекста теперь считается ошибкой, хотя этот индикатор не
доказывает отсутствие любой возможной внутренней обрезки Ollama ниже границы.

MCP stdio проверяется отдельным клиентом. В измерителе B/C вызывается тот же слой
чтения непосредственно; накладные расходы MCP-транспорта не включены в сравнение.
Механизм коррекции D также остаётся отдельным экспериментом, не включён в API.
Для прототипа MCP используется поддерживаемая ветка SDK 1.x с ограничением <2:
[документация SDK](https://github.com/modelcontextprotocol/python-sdk/tree/v1.x).
Поля длительностей и структурированный формат проверялись по
[Ollama API](https://docs.ollama.com/api/chat).
