# Аудит стенда B0–B3 — 16.11.2026

Область: `answer_benchmark.py`, `answer_dataset.py`, `answer_metrics.py`,
`answer_review.py`, снимки норм и пути вызова поиска/провайдера. Проверены исходники,
протокол пилота и детерминированные тесты. Модели, внешние API и новые юридические
эксперименты не запускались. Исходные результаты 15.11 не изменены.

## Подтверждённые дефекты и исправления

1. **Профиль мог менять заявленный бюджет.** Адаптер Ollama накладывает options
   профиля поверх аргументов temperature/max_tokens. Поэтому стенд объявлял 0.0 и
   2048/1024, но профиль мог фактически задать другую температуру или `num_predict=-1`.
   Теперь MeteredGateway задаёт эти два параметра в эффективных provider_options;
   сохранённая конфигурация не меняется. Регрессия использует настоящий адаптер с
   MockTransport и проверяет тело HTTP для ANSWER и VERIFY.
2. **HTTP-таймаут мог считаться нецензурированным сбоем.** Адаптер оборачивает
   ReadTimeout в ProviderError. Проверка только TimeoutError теряла причину.
   Теперь проверяется цепочка cause/context, включая httpx.TimeoutException.
   Регрессия подтверждает одну HTTP-попытку, `censored=true` у вызова и случая.
3. **Отмена теряла текущую строку и расходы уже начатых вызовов.** Раньше строка
   попадала в report только после завершения evaluate_case. Теперь строка и текущая
   попытка сохраняются до вызова и после него, а также при завершении случая.
   CancelledError сохраняет статус `interrupted`, имеющиеся результаты, длительности
   и признак цензурирования, после чего отмена распространяется дальше.
   Сбой записи не должен обнулить предыдущий отчёт: write_json использует временный
   файл и replace. Проверены отмена ожидающего вызова и ошибка замены файла.
4. **Равное число повторов не гарантировало сопряжение.** Bootstrap принимал,
   например, B2 с repeat 0/1 и B3 с repeat 0/2, а также дубликаты повторов.
   Теперь при наличии repeat проверяются уникальность, одинаковые наборы repeat ID
   и согласованность семейства случая. Старый интерфейс строк без repeat сохранён.
   Неполные человеческие оценки по-прежнему дают `unresolved` без вывода о превосходстве.

## Дополнительный учёт и проверенные инварианты

- Сводка теперь показывает наблюдённые chat input/output tokens и число вызовов
  с неизвестным usage. Если хотя бы одно значение неизвестно, полный total = null;
  сумма известных значений сохраняется отдельно. Вызовы embedding без usage
  посчитаны отдельно. Денежная стоимость остаётся null.
- B0 получает разрешение использовать собственные знания; B1–B3 — только источники.
  Это явное условие текущего протокола. B1 — лексический поиск без расширения;
  B2/B3 — один гибридный поиск с расширением, реранкер выключен.
- Начальные сообщения B2 и B3 совпадают при одинаковой выдаче. B3 делает один
  вызов проверяющего и не более одной генерации исправления. Бюджеты 2048/1024/2048
  проверены тестом. Ошибка JSON не вызывает скрытой повторной генерации.
- В генератор и проверяющий передаются question/facts/date/issues и найденные нормы,
  без source consultation, candidate_articles, machine_draft или gold. Диагностика
  O отдельно требует принятого gold и сверки норм со снимком.
- Самопроверка не присваивает solution_pass. Успешно сгенерированные ответы остаются
  без оценки, операционные сбои остаются в знаменателе. Слепой пакет скрывает методы;
  импорт оценок проверяет хеши отчёта, набора и ответа и наличие принятого эталона.

## Ограничения и следующий шаг

Синхронная запись контрольных точек входит в elapsed случая; новый report явно
содержит описание recording. Поэтому задержки будущих прогонов нельзя напрямую
приписывать улучшению/ухудшению модели относительно старых пилотов. Внезапное
завершение процесса может оставить последний checkpoint в состоянии running;
серверный расход после обрыва HTTP неизвестен и не становится нулевым.

Адаптер embedding возвращает только векторы, поэтому его токены и серверные
длительности по-прежнему неизвестны. Это ограничение явно показано в сводке;
изменения общего адаптера не входили в этот аудит. Независимого человеческого
эталона и калибровки оценщиков пока нет; юридическая точность не установлена.
Новые механизмы и реранкер в продукт по результатам аудита не включаются.
