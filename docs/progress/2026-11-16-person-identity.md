# Уточнение одноимённых участников — 16.11.2026

По прямому поручению «Пофикси» устранено молчаливое объединение обнаруженных
одноимённых людей при первом появлении и реализован API-сценарий уточнения.
Это продолжение [аудита](2026-11-16-audit-summary.md); предыдущие отчёты и
результаты сохранены как история.

## Реализовано

- deid назначает неподтверждённым PERSON отдельные метки. Повторное имя в вопросе
  или совпадение с именем сеанса вызывает `IdentityRequired` до записи состояния.
- Основной API и сервис deid возвращают 409 `person_identity_required` с
  предварительным обезличенным текстом и диапазонами для подтверждения.
- Явные привязки разрешают одного или разных участников, известную метку текущего
  сеанса или повторное использование неперсонального actor ID. Они связаны с
  точной строкой через SHA-256 и не могут молча примениться к изменившемуся тексту.
- Некорректные привязки дают безопасный 422. Поля поддержаны для текста, голоса
  и фото, для локального и HTTP-клиентов. Пока уточнения нет, юридический Pipeline
  не запускается, вопрос не сохраняется и номер реплики не расходуется.
- Подтверждённые связи/псевдонимы хранятся в отдельном RAM-состоянии; rollback,
  TTL, удаление и лимиты охватывают также это состояние. В постоянную историю
  и trace привязки и исходные ФИО не попадают.
- Исправлен обнаруженный обход через детектор: заглавная должность перед полным
  ФИО (`Директор Иванов Иван Иванович`) больше не разбивает это имя на три находки.

Контракт, пример повторного запроса, мультимедиа и ограничения:
[решение 0002](../decisions/0002-person-identity.md).

## Проверки

- Полный набор **407 passed за 72.36 с** на новой отдельной БД
  `yourist_identity_20261116_test`; перед запуском проверено отсутствие её точного
  имени. Рабочая БД для тестов не использовалась.
- Ruff check/format прошли для всех **183 Python-файлов**; git diff --check прошёл.
- Отдельные 89 deid и 10 transport тестов не складываются с полным набором.
- Регрессии: исходные два одноимённых работника; одно лицо в разных падежах после
  подтверждения; выбор из двух ранее известных меток; межрепличные actor IDs;
  rollback и удаление RAM; неверные/устаревшие/частичные привязки; исходные Unicode
  диапазоны после первого прохода; HTTP и мультимедиа; отсутствие поиска,
  генерации, исходных данных в истории и записи вопроса до подтверждения.

Повтор существующего синтетического набора сохранён отдельно:
`backend/evaluation/results/2026-11-16-identity-clarification/` со снимком данных,
результатами и хешами исходников. Два случая требуют уточнения, две пары личности
не разрешены; для них identity_merges/splits = null и число оценённых пар = 0.
Среди обработанных без уточнения пар смешений и ложных разделений 0. Это не
«100% точность»: воздержания учтены отдельно, набор просмотрен при разработке.
Детекция осталась TP=13, FP=3, FN=2, восстановление 11/15, сохранность вне меток
16/16. Независимой юридической оценки по этим данным нет.

## Состояние

Правки локальные на feature/local-reranker поверх ab2d53e, вместе с предыдущими
незакоммиченными исправлениями аудита. Коммит, push, merge и релиз не выполнялись.
Внешние API и модели не запускались; тесты распознавания и генерации используют
подменные провайдеры. Старые результаты не перезаписывались; `10` и `backups/`
не менялись. Человеческая разметка остаётся отложенной задачей владельца.

Изменение намеренно требует подтверждения также для настоящего одного человека
при повторе имени. Клиенты должны обработать новый 409; интерфейс выбора в этом
репозитории не реализован. Пропуски детектора остаются отдельным ограничением.
При изменении OCR/STT текста нужно новое уточнение. Исторически смешанные данные
нельзя достоверно восстановить без исходных сведений.
