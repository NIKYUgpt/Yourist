# Работа над Yourist

## Синхронизация перед началом

Перед каждым новым заданием над проектом, в том числе после перерыва,
обязательно синхронизируй текущую рабочую ветку **до анализа кода и правок**:

```shell
git status --short --branch
git branch --show-current
git pull --ff-only --no-autostash
```

Команда использует upstream текущей ветки. Не подставляй автоматически main,
develop или ветку из исторического отчёта и не переключай ветки без основания
в текущем задании. Если upstream не задан, сначала определи правильную удалённую
ветку; не подтягивай произвольную ветку вместо неё.

`--ff-only` запрещает неявные merge/rebase, `--no-autostash` — автоматическое
скрытие локальной работы. Сначала учитывай существующие изменения. Не выполняй
reset/clean/stash, удаление файлов или force, чтобы обойти отказ pull. При
ошибке сети, расхождении веток или конфликте локальных файлов разберись с причиной
и сообщи о проблеме синхронизации; не выдавай такой pull за успешный и не начинай
новые правки поверх непроверенного состояния. Чтение для диагностики допустимо.

Наличие посторонних untracked-файлов само по себе не требует их удаления:
не открывай и не добавляй их ради синхронизации.

После успешного pull перечитай обновлённые AGENTS.md и относящиеся к заданию
инструкции/контекст. Pull выполняется один раз перед заданием, не перед каждой
командой. Если в рамках задания нужна другая ветка, синхронизируй её перед работой.

## Контекст и продолжение

После синхронизации начни с [HANDOFF.md](HANDOFF.md), затем открывай только
необходимые исходники и документы. Текущий запрос владельца важнее исторических
планов. Человеческая юридическая разметка отложена владельцем; автоматически
не начинать её и не отправлять пакеты участникам.

Для совместной работы достаточно репозитория. Личный Obsidian владельца и его
приватные данные не требуются. Пользовательский `10` и `backups/` в локальном
каталоге владельца не относятся к заданиям проекта: не открывать, не менять
и не добавлять их без прямого поручения.
