# Yourist

Экспертная система для правового анализа на базе ИИ. Отвечает на вопросы по законодательству РФ, опираясь на актуальные редакции нормативных актов, и проверяет собственные ответы.

> Статус: ранняя разработка. Готовы каркас backend (регистрация, роли, API, CI),
> корпус законов (Трудовой кодекс РФ со всеми редакциями с 14.07.2022), подключение
> нейросетей — локальных и по API, — поиск норм на заданную дату и конвейер ответа:
> обезличивание вопроса → поиск норм → ответ со ссылками → программная проверка ссылок.

## Что планируется

- ответы с обязательными ссылками на статьи в действующей редакции;
- собственная база законов с историей редакций (источник — официальный портал pravo.gov.ru), начиная с трудового права;
- обезличивание персональных данных до обращения к ИИ — классическими методами и с помощью ИИ;
- проверка ответа вторым ИИ и программная проверка ссылок на нормы;
- работа с локальными моделями или через API (YandexGPT, GigaChat; также OpenAI, Claude, Gemini, DeepSeek, Qwen), переключение в админке;
- клиенты: веб, мобильное и десктопное приложения.

## Стек

Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL 16 + pgvector, lxml, httpx, Ollama, Docker Compose, GitHub Actions.

## Архитектура

Модульный монолит: один код, разбитый на модули с жёсткими границами. Каждый модуль
владеет своей схемой БД (`auth`, `corpus`, `ai`, `search`, `assistant`). Отдельными
сервисами запускается то, у чего своя нагрузка, свой жизненный цикл или особые
требования к безопасности.

```
клиенты ──▶ api (:8000)      auth: пользователи, роли, токены
       │      │              assistant: вопросы и ответы; search: поиск норм
       │      │              ai: настройки нейросетей
       │      └──▶ deid      обезличивание: граница персональных данных
       │           (внутр.)  (без БД, порт наружу не публикуется)
       └──▶ corpus (:8001)   corpus: законы и редакции; построение поискового индекса
                 │                 │ синхронизация по расписанию
                 ▼                 ▼
            PostgreSQL       actual.pravo.gov.ru
            + pgvector
                             Ollama (на хосте, GPU) / API: YandexGPT, GigaChat, …
```

- **api** выдаёт access-токен (JWT) с ролью пользователя;
- **deid** принимает запросы только от api — по короткоживущему служебному токену;
- **corpus** проверяет подпись и роль в токене сам, без обращения к таблице пользователей;
- **migrate** — одноразовый контейнер: применяет миграции, после него стартуют api и corpus;
- **Ollama** работает на хосте (ей нужна видеокарта), контейнеры обращаются к ней
  по `host.docker.internal`.

## Корпус законов

Источник — раздел «Тексты правовых актов с внесенными изменениями» официального портала
правовой информации (actual.pravo.gov.ru), где тексты имеют официальный статус
(Указ Президента РФ от 03.03.2022 № 90). Публичного API у портала нет; используется
JSON API, через который работает сам сайт, — с паузой между запросами и повторами при сбоях.

Как устроено:

- редакция разбирается по оглавлению источника: часть кодекса → раздел → глава → статья →
  часть статьи / пункт / подпункт; пометки «(В редакции …)» хранятся отдельно от текста нормы;
- статьи хранятся без повторов: одинаковый текст в разных редакциях — одна версия,
  редакция — это сопоставление «номер статьи → версия»;
- отсюда — текст статьи на любую дату, история её изменений и разница между двумя датами;
- синхронизация раз в сутки: новые редакции скачиваются, актуальная и будущие
  перепроверяются по хешу (источник может их пересобрать), исчезнувшие помечаются;
- сырые ответы источника сохраняются — корпус можно пересобрать без повторного скачивания.

По умолчанию отслеживается Трудовой кодекс РФ; другие акты добавляет администратор
(`GET /corpus/search`, затем `POST /corpus/acts`).

## Нейросети

Каждая задача, где нужна нейросеть, настраивается в двух вариантах — локальная модель
и внешний API, — а общий переключатель `mode` (`PUT /admin/ai/mode`) переводит все задачи
сразу. При необходимости отдельной задаче можно задать свой режим.

| Задача | Локально (по умолчанию) | Через API (по умолчанию) |
|---|---|---|
| `answer` — ответ на вопрос | Ollama `qwen3:8b` | GigaChat `GigaChat-2-Max` |
| `verify` — проверка ответа | Ollama `qwen3:8b` | YandexGPT `yandexgpt` |
| `deid` — поиск персональных данных | Ollama `qwen3:8b` | YandexGPT `yandexgpt` |
| `embed` — векторы для поиска | Ollama `bge-m3` (на процессоре) | YandexGPT `text-search` |

Провайдеры: Ollama (локально), YandexGPT и GigaChat (данные обрабатываются в РФ),
OpenAI, Claude (Anthropic), Gemini, DeepSeek, Qwen (зарубежные). Для задачи `deid`
зарубежные провайдеры запрещены: в неё попадает исходный текст пользователя.

- ключи и адреса — только в `.env` (см. `.env.example`), в БД и в админке — лишь выбор
  провайдера и модели; админка показывает, у каких провайдеров ключи заданы;
- имена моделей у API-провайдеров меняются, поэтому актуальный список берётся у самого
  провайдера: `GET /admin/ai/providers/{name}/models`; пробный запрос —
  `POST /admin/ai/providers/{name}/check`;
- для зарубежных API, недоступных из РФ напрямую, — прокси `AI_PROXY_URL`;
- GigaChat использует сертификаты НУЦ Минцифры: если TLS-проверка не проходит, укажите
  путь к сертификату в `GIGACHAT_CA_BUNDLE`;
- YandexGPT вызывается с заголовком `x-data-logging-enabled: false` — запросы
  не сохраняются Яндексом для обучения;
- векторы локально считаются на процессоре (~0,2 с на запрос): на 8 ГБ видеопамяти
  модель ответа и модель векторов иначе вытесняют друг друга на каждом вопросе.

> Проверено вживую: Ollama и YandexGPT (чат, JSON-режим, эмбеддинги `text-search`;
> 27.10.2026). Остальные клиенты API-провайдеров написаны по документации и исходникам
> официальных SDK и покрыты тестами с подменой ответов; с реальными ключами пока
> не проверялись.
>
> YandexGPT: идентификатор каталога (`YANDEX_FOLDER_ID`) — в консоли Yandex Cloud рядом
> с названием каталога; кроме моделей YandexGPT, через тот же ключ доступны размещённые
> у Яндекса открытые модели (полный список — `GET /admin/ai/providers/yandex/models`).

## Поиск по нормам

- статьи режутся на фрагменты по частям и пунктам (~1200 символов); части подписываются
  «[ч. 2]», вводные слова длинной части повторяются в каждом её фрагменте;
- индекс строится по уникальным версиям статей, а не по редакциям: 784 версии ТК РФ
  дают 1793 фрагмента вместо десятков тысяч;
- поиск гибридный: полнотекстовый (PostgreSQL, вес редких слов как в BM25) и векторный
  (pgvector), результаты объединяются по рангам (RRF); явно названная статья («ст. 81»)
  попадает в выдачу в любом случае;
- ищутся только версии, действовавшие на дату вопроса;
- векторы разных моделей хранятся раздельно — при переключении local/api недостающие
  досчитываются сервисом corpus, а старые остаются.

## Обезличивание

Вопрос пользователя до любой языковой модели проходит сервис `deid`:

1. **правила** — шаблоны с проверкой контрольных сумм: ИНН, СНИЛС, ОГРН/ОГРНИП, номер
   карты (алгоритм Луна), счёт, паспорт (по контексту), телефон, email, адрес, ссылки
   на соцсети, организации («ООО «…»»), дата рождения. Остальные даты, суммы, номера
   статей и приказов не трогаются — они важны для ответа;
2. **словарь имён** — морфологический анализатор pymorphy3 (словари OpenCorpora) с
   вероятностями разборов: ФИО, «Фамилия И. О.», имена. «Вера» в начале предложения
   останется словом, «Роза из бухгалтерии» будет скрыта;
3. **языковая модель** (включается в админке, `deid_llm`) получает уже замаскированный
   текст и может только добавить находки — то, что пропустили правила.

Найденное заменяется метками `[ФИО_1]`, `[ТЕЛЕФОН_1]`…; одно лицо в разных падежах
получает одну метку. Таблица «метка → значение» нигде не сохраняется: значения
подставляются обратно только в ответ, который возвращается автору вопроса. Если сервис
недоступен, вопрос дальше не идёт.

## Ответ на вопрос

1. обезличивание (см. выше);
2. поиск норм, действовавших на дату вопроса (по умолчанию — сегодня);
3. ответ модели по нумерованным источникам: `[2]` и «ч. 1 ст. 81 ТК РФ»;
4. **программная проверка ссылок** (без нейросетей) — по корпусу на дату вопроса:
   - статья существует и не утратила силу, ссылка `[n]` указывает на реальный источник —
     иначе ошибка;
   - названные часть, пункт, подпункт в статье есть; статья была среди источников;
     цитата в «кавычках» дословно есть в источниках — иначе предупреждение;
   - если известна будущая редакция статьи — пометка «изменится с ДД.ММ.ГГГГ»;
   - ссылки на акты, которых нет в корпусе (ГК РФ, федеральные законы), помечаются
     как непроверяемые;
5. при ошибках — одна попытка исправления с их перечнем; остаётся лучшая из попыток.

Итог проверки — `passed`, `warnings` или `failed` — возвращается вместе с ответом, ссылками
и источниками. Проверка подтверждает, что ссылки настоящие, но не то, что вывод из них
следует: это задача проверяющей модели (этап 5).

В БД хранятся только обезличенные вопрос и ответ, все попытки и трасса этапов (время,
модели, токены) — для отладки и оценки. Пользователь может удалить свой вопрос; при
удалении пользователя его вопросы удаляются.

Ориентиры по скорости (ручной прогон 10 вопросов; RTX 4060 Ti 8 ГБ, `qwen3:8b`):
обезличивание ~0,4 с, поиск ~0,2 с, ответ 3–8 с; первый вопрос после простоя дольше
на время загрузки модели. Это не оценка качества — для неё будет отдельный стенд (этап 7).

## Быстрый старт (Docker)

```bash
cp .env.example .env
ollama pull qwen3:8b && ollama pull bge-m3      # локальные модели (на хосте)
docker compose up -d --build
```

- API: http://127.0.0.1:8000/api/v1, документация — http://127.0.0.1:8000/docs
- Корпус: http://127.0.0.1:8001/api/v1, документация — http://127.0.0.1:8001/docs

Первая синхронизация Трудового кодекса (38 редакций) и построение поискового индекса
занимают несколько минут: ход виден в `docker compose logs -f corpus`.

Создать администратора (или назначить администратором уже зарегистрированного пользователя):

```bash
docker compose exec api python -m app.cli create-admin --email admin@example.com
```

В dev-режиме письма не отправляются, а пишутся в лог: `docker compose logs api`.

## Разработка backend без Docker

База всё равно запускается в контейнере:

```bash
docker compose up -d db
cd backend
python -m venv .venv            # Windows: py -3.12 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload                          # api
uvicorn app.corpus_main:app --port 8001 --reload       # corpus
uvicorn app.deid_main:app --port 8002 --reload         # deid (DEID_URL=http://127.0.0.1:8002)
```

Без `DEID_URL` api обезличивает вопросы в своём процессе — так удобнее при разработке.

Проверки (тестовая база `yourist_test` создаётся автоматически):

```bash
ruff check . && ruff format --check .
pytest
```

Новая миграция после изменения моделей:

```bash
alembic revision --autogenerate -m "что изменилось"
```

## Роли

- **user** — пользователь;
- **support** — поддержка: видит пользователей, дальше — очередь обращений;
- **admin** — полный доступ, управление ролями и настройками.

## Безопасность

- пароли хешируются Argon2id;
- access-токен (JWT) живёт 15 минут, refresh — 30 дней; refresh хранится в БД только в виде хеша и меняется при каждом обновлении;
- повторное предъявление уже использованного refresh-токена закрывает все сессии пользователя;
- ответ и время ответа одинаковы для «нет такого email» и «неверный пароль»;
- PostgreSQL и API в compose слушают только 127.0.0.1;
- исходный текст вопроса обрабатывается только сервисом `deid` (и, если включён второй
  проход, локальной или российской моделью); в БД, журналы и внешние API попадает
  обезличенный текст;
- `deid` не подключается к БД, его порт не публикуется, вызывать его можно только
  со служебным токеном api; при его недоступности вопрос не обрабатывается;
- фиксируется момент согласия на обработку персональных данных (ст. 9 152-ФЗ).

```
backend/
  app/
    core/              настройки, безопасность, роли, почта, проверка токена без БД
    db/                подключение к БД, базовая модель, реестр моделей модулей
    modules/
      ai/              провайдеры нейросетей, модели по задачам, переключатель local/api
      assistant/       конвейер ответа, промпты, проверка ссылок, история вопросов
      auth/            пользователи, роли, регистрация, токены
      corpus/          клиент источника, парсер, синхронизация, чтение редакций
      deid/            обезличивание: правила, словарь имён, проход моделью; сервис и клиент
      search/          нарезка статей, индекс (pgvector), гибридный поиск на дату
    main.py            точка входа api
    corpus_main.py     точка входа сервиса корпуса
    deid_main.py       точка входа сервиса обезличивания
    cli.py             служебные команды
  migrations/          миграции Alembic (общая история, схемы модулей)
  tests/
docker-compose.yml
```
